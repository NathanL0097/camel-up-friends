# 好友桌游馆视觉系统

## Art direction

平台是“私人桌游俱乐部”：暖纸、墨色、编辑式标题和清楚的入座流程。平台统一阅读层级、间距、焦点管理、操作规则与动效原则，不强制每款游戏使用同一种面板或棋盘结构。

| 游戏 | 专属视觉与材质 |
| --- | --- |
| 骆驼 | 赛场海报、沙丘、彩色木质驼队、竞猜票券 |
| 阿瓦隆 | 旧金纹章、蚀刻圣杯、夜蓝、中央仪式圆桌与两侧席位 |
| 骰城 | 装饰艺术、墨绿毡布、刻印筹码、钞票、独立骰盅操作区 |
| 列车 | 木板车厢、铁件、荒野版画、铁路票据与通缉令 |
| 女巫镇 | 木刻小镇、档案纸、煤黑、蜡封与血锈色审判标记 |

不复制商业桌游原图；专属资产使用项目原创矢量。诡镇调查不属于本轮专属美术投入范围。

## Design tokens

- 色彩：`ink / paper / surface / surface-raised / border / muted / accent / success / warning / danger`。
- 字体：功能信息使用中文无衬线；游戏标题和重大结果使用中文衬线。字阶12/14/16/20/28/40px；装饰小字不承担关键规则。
- 间距：4px 基础网格，优先使用 8、12、16、24、32、48px。
- 圆角：纸张、票据和纹章边框以1–5px为主；实体骰盅、筹码、棋盘按材质定义，避免全站大圆角卡片。
- 阴影：只用于实物层次与遮挡关系，最多两层；不使用随机霓虹、持续发光或玻璃面板。
- 卡牌：稳定比例、清楚边界、明确的可点击/选中/不可用状态。
- 棋盘：区分环境层、棋盘层、棋子层与 HUD 层，避免操作卡遮住主要状态。
- 图标：使用单色徽章或线性符号；Emoji 只能作为辅助，不承担主要身份识别。
- 玩家头像：按游戏世界使用纹章、通缉头像、席位标记；均保留完整姓名、本人/行动/离线等文字。

## Interaction states

- Primary：当前最重要且可立即执行的动作。
- Secondary：同层辅助动作。
- Quiet：规则、邀请、查看详情等低风险动作。
- Danger：不可逆或明显负面动作。
- 所有交互必须具有 hover、pressed、focus-visible、selected 和 disabled 状态。
- 当前玩家、本人、房主、离线、等待和已确认必须同时通过形状/文字和颜色表达，不能只依赖颜色。

## Motion language

- L1 Micro：100–200ms（基线140ms），用于按压、选中与切换。
- L2 Gameplay：200–400ms（基线320ms），用于界面与回合变化；可读的实体路径移动可延至700ms。
- L3 Major：400–1200ms（基线700ms），用于受击、匿名翻牌、重大结果。另加独立阅读停留。
- L4 Cinematic：分段铺垫、揭晓、冲击和稳定结果（基线1100ms用于单段），只用于冲线与终局等少数高情绪时刻。
- Ease-out：`cubic-bezier(.2,.75,.25,1)`。
- Spring：`cubic-bezier(.18,.9,.28,1.18)`。
- Settle：`cubic-bezier(.22,.7,.2,1)`。
- 每次只突出一个主要事件；动画必须解释状态变化，而不是制造持续干扰。
- 文字密集结果按内容延长停留时间，必要时由玩家确认继续。
- 必须支持 `prefers-reduced-motion`。
- 相同公开事件只能演一次。其他玩家提交、确认或连接状态更新不能重建当前卡牌、重播身份揭示或抢走焦点。
- 普通落骰反馈发生在骰子托盘内；复杂板块和派彩才使用独立结果场景。列车普通动作有界自动推进，离线玩家不阻塞结果阶段。

## Sound architecture

`public/platform-audio.js` 集中管理 UI / gameplay / flow / major 四级音效。默认静音，用户手势解锁，一个 AudioContext，全局音量、事件去重、并发上限、后台静默与跨标签设置同步。小音色手势后预热，其余按需缓存；声音工厂可替换为合法音频资产。游戏规则不调用声音；客户端从确认后的呈现事件触发。

## Responsive principles

- 桌面端优先形成“玩家状态 / 主棋盘 / 操作反馈”的清楚层级。
- 移动端采用当前任务优先：行动与本人可用资源靠前，次要历史与详情下移或折叠。复杂驾驶舱使用明确分区，不能整体缩成小字。
- 横向滚动只用于规则上天然横向的对象，并必须提供位置导航；普通页面不得依赖桌面最小宽度。
- 触控目标不小于44px，正文保持可读，底部安全区不得遮挡主要动作。对话框按可用内容宽度布局，不能使用会叠加内边距的视口宽度造成横向溢出。
- 每批改造均在1240×760与390×844实际浏览器中复核。自动测试通过是必要条件，不代替画面、节奏和操作验收。
